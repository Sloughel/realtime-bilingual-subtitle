## 4. 断网重连缺陷（已定位，v0.1.5 修复）

21:23 前后多次断网后，媒体模式出现“重连后很快停止连接”：

- 重连中 `CaptureService` 调用 `stopAudio()`，`MediaSource.stop()` 释放了 1×1 VirtualDisplay；
- 重连成功后又用**同一个 `MediaProjection`** 创建新的 `MediaSource`/VirtualDisplay；
- Android 的 MediaProjection 不允许释放后重建（一个投影会话只能创建一个 VirtualDisplay），
  启动失败后 `fail()` 关闭 WebSocket 与前台服务。
- 修复（v0.1.5）：重连期间**保持音频源与 MediaProjection 存活**，`WsClient` 未就绪时丢弃帧；
  重连成功后同一音源继续发送，不再重建 `MediaSource`。
- 状态：代码已改、构建通过；**待真机复测**。复测判据：媒体模式断网 5s → 恢复后 30s 内继续出字幕，且服务不停止。

## 5. 结论与下一步

1. 本次 20 分钟数据不是 30 分钟，也不满足“无停顿”的 NFR-01 采样条件；只作为诊断。
2. 正式 NFR-01 仍用 2026-10-19 的 83 句 P95 2475ms，或等 v0.1.5 干净复测 100+ 句后替换。
3. 媒体模式重连缺口已修复，需装 v0.1.5 复测；若复测仍失败，再查 MediaProjection 生命周期。
4. 若干净复测 raw P95 仍 >3s，再考虑把 ASR 与翻译解耦（当前串行 worker 会被慢翻译阻塞）或增加翻译截止时间；本次先不改管道，避免在未复测前引入新变量。
