## 1. 引言

### 1.1 编写目的

本文档定义实时双语字幕系统的功能需求、非功能需求、约束与验收标准，作为《02-系统架构设计》《03-接口与通信协议设计》《04-开发计划与任务分解》以及后续编码、测试和课程验收的依据。

### 1.2 项目背景

AI 实时字幕翻译并非空白领域：哔哩哔哩的 AI 字幕、讯飞听见、华为鸿蒙高版本均已实现实时的语音转写与翻译，说明该能力在商业产品中已经成熟。但观察现有产品可以发现两点不足：其一，多为闭源商业服务，功能形态受厂商限制，难以按需定制或集成进自有系统；其二，也是最关键的一点——音频需要上传至厂商云端处理，这对有保密要求的场景构成隐患。例如企业线上会议、涉密沟通中，音频一旦离开内网即存在泄露风险。

因此本项目以**隐私**为切入点：设计一个开源、可自托管（self-hosted）的实时双语字幕系统供企业或个人开发者使用。移动端采集的音频仅经局域网发送到自有的处理主机；基础版仅将识别出的文本送往云端翻译；扩展为本地模型后，音频与文本均不出内网。企业可将其部署于公司自有服务器，员工的手机作为客户端，满足保密会议等场景的合规要求。该企业场景作为项目**愿景**与扩展方向，不纳入本次课程项目的交付目标。

本项目课程版采用"手机采集音频 → 主机智能处理 → 手机悬浮窗显示字幕"的架构：手机抓取媒体声音或麦克风声音，经局域网传给主机，主机使用本地语音识别（faster-whisper）与云端大模型翻译（DeepSeek）处理后回传，手机以悬浮窗形式呈现实时双语字幕。

### 1.3 范围

**基础版（v1.0）包含：**

- Windows 主机服务端（语音识别 + 翻译 + 字幕回传）
- Android 客户端（麦克风采集、媒体声音采集两种模式）
- 局域网通信（WebSocket）
- faster-whisper 语音识别（CUDA 加速）
- DeepSeek API 翻译，基础方向英→中
- 悬浮窗双语字幕显示

**不包含（列入扩展计划，按优先级从高到低排列）：**

| 编号 | 扩展项 | 优先级 |
|---|---|---|
| E1 | 互联网连接（公网访问） | 1 |
| E2 | 翻译使用本地部署模型（隐私目标：音频与文本全链路不出内网） | 2 |
| E3 | 主机支持 Linux | 3 |
| E4 | 移动端支持 iOS、鸿蒙 | 4 |
| S1 | 语言扩展：支持扩展到英中之外的语言对，以中日互译（ja↔zh）作扩展演示 | 远期探索 |

**项目愿景**：作为开源软件，供企业或个人部署于自有服务器并配合本地模型使用，使涉密场景（如保密会议）获得实时双语字幕；本愿景依托 E2/E3 扩展实现，不构成本次课程项目的验收目标。

### 1.4 术语表

| 术语 | 说明 |
|---|---|
| ASR | 自动语音识别（Automatic Speech Recognition），将音频转写为文本 |
| VAD | 语音活动检测（Voice Activity Detection），判断音频中是否有语音 |
| LLM | 大语言模型（Large Language Model），本项目用于翻译 |
| 悬浮窗 | 悬浮于其他应用界面之上的系统级浮层窗口 |
| MediaProjection | Android 屏幕/音频投影 API，媒体声音采集依赖它获得用户授权 |
| 端到端延迟 | 一句话结束（人说完）到该句字幕上屏的时间间隔 |
| 断句 | 依据静音间隔把连续语音流切成句子的过程 |

## 2. 总体描述

### 2.1 产品定位

一款开源、可自托管的实时字幕工具：手机负责"听"（音频采集与上传），主机负责"想"（识别与翻译），手机悬浮窗负责"显示"（双语字幕）。基础版面向个人外语内容观看场景；同时以"音频不出内网、模型可本地化"的架构为企业保密场景（如线上会议）预留移植能力——后者为项目愿景，不纳入本次课程交付目标。

### 2.2 系统上下文

```mermaid
flowchart LR
    U[终端用户] -->|观看视频/对话| PH[Android 客户端]
    D[部署者] -->|部署 / 配置 / 维护| HOST[Windows 主机服务端]
    PH <-->|WebSocket 局域网| HOST
    HOST <-->|HTTPS 翻译请求| LLM[DeepSeek API]
```

### 2.3 用户特征与角色

本项目为开源、可自托管软件，使用者按职责分为三个角色：

| 角色 | 说明 | 技术要求 | 核心诉求 |
|---|---|---|---|
| 终端用户 | 使用 Android 客户端观看字幕 | 无技术背景要求，能完成权限授权、连接同一 Wi-Fi、填写服务器地址即可 | 连接简单、字幕准确及时 |
| 部署者 | 在自有主机或服务器上部署并维护服务端。个人开发者用于自用；企业工程师为公司搭建 | 需基本的命令行操作与环境配置能力 | 部署文档清晰、配置集中、故障可自诊断 |
| 二次开发者 | 阅读与修改源码，扩展语言方向或接入自有系统（开源贡献者、企业集成者） | 需开发能力 | 代码结构清晰、接口可扩展、协议文档完备 |

**角色关系**：部署者与二次开发者常为同一人（个人开发者自托管时通常也会改代码）。企业场景下，企业工程师（部署者/二次开发者）完成部署与定制后，交付给员工（终端用户）日常使用——这是一条"部署者/二次开发者 → 终端用户"的服务链，而非彼此独立的角色。

**本项目交付范围**：课程项目主要面向**终端用户**与**部署者**——前者对应 M2/M3 的客户端与联调，后者对应 M0 的环境准备与部署文档（FR-18~FR-20）。面向二次开发者的完整支持（贡献指南、插件化扩展点、代码走读文档）不在本次交付目标内；但架构上为其预留扩展边界（见 02 文档 §3 架构原则与 §9 扩展预留设计）。

### 3.3 消息级接口的最小定义与依赖边界

本文档只定义**消息类型与语义**（回答"两端交换什么"）；**字段级编码**（字节布局、数据类型、
取值范围、错误码取值）不在本文档重复定义，其唯一权威定义见《03-接口与通信协议设计》对应章节。

| 消息 | 方向 | 语义（本文档定义） | 字段级定义（03 文档） |
|---|---|---|---|
| 音频帧 | 客户端 → 服务端 | 承载一个 100ms 分片的 16kHz 单声道 PCM16 音频，携带递增序号供丢帧检测 | §3 音频帧格式 |
| `hello` | 服务端 → 客户端 | 连接建立后的握手应答，声明协议版本与本次会话的服务端限制 | §2 连接与握手 |
| `config` | 客户端 → 服务端 | 提交会话配置：采集模式、源/目标语言、采样率、分块时长 | §4.1 |
| `config_ack` | 服务端 → 客户端 | 确认配置已生效；未采纳项在 `warnings` 中回报 | §5.1 |
| `start` / `stop` / `reset` | 客户端 → 服务端 | 会话控制：开始处理 / 冲刷当前句后停止 / 丢弃未断句音频 | §4.2 |
| `subtitle` | 服务端 → 客户端 | 回传一句双语字幕：原文、译文、句序号、音频时间区间、各阶段耗时 | §5.2 |
| `error` | 服务端 → 客户端 | 回报错误码、说明与可恢复性 | §5.3、§6 |
| `ping` / `pong` | 双向 | 心跳保活 | §4.2、§5.3 |

**边界声明**：新增语言方向与全部扩展项（E1~E4、S1）均**不新增消息类型**，只扩充枚举取值或
替换后端实现，故 03 文档的协议版本可保持不变（版本演进策略见 03 文档 §12）。

## 4. 非功能需求

| 编号 | 类别 | 实现优先级 | 指标（可验证判据） | 验证方式 | 来源 |
|---|---|---|---|---|---|
| NFR-01 | 性能-延迟 | 高 | 句末→字幕上屏 **P95 ≤ 3s**（逐句记录 `created_ms - end_ms`，取 100 句样本的 95 分位）。预算分解：采集缓冲 100ms + 断句等待 ≤500ms + ASR ≤800ms + 翻译 ≤1500ms + 渲染 ≤50ms | 延迟统计报告 | AI 默认（待确认：3s 目标与各项预算分配） |
| NFR-02 | 性能-带宽 | 低 | 上行音频 ≤ 40KB/s（16kHz×16bit 单声道理论值 32KB/s，含协议头余量） | 实测抓包 | 行业惯例（由 ADR-06 音频规格推算） |
| NFR-03 | 准确性 | 高 | **识别**：在 100 句英文标准口音语料（TED 风格，总时长 ≥10 分钟）上 **WER ≤ 10%**；以人工逐句标注为基准，标点与大小写差异不计错。**翻译**：抽取连续 100 句，由 2 名评审独立判定语义是否正确，**一致通过率 ≥ 95%**；分歧句由第 3 人裁定并计入结果 | 语料测试 + 评审记录表 | AI 默认（待确认：阈值与语料规模） |
| NFR-04 | 稳定性 | 高 | 连续运行 **≥30 分钟**无崩溃、无内存持续增长；断线后 **≤30s** 自动恢复 | 系统测试 | 行业惯例 |
| NFR-05 | 资源 | 中 | 服务端 GPU 显存占用 **≤6GB**（开发机 RTX 4060 8GB）；空闲时 ≤1GB。手机端采集期间内存增长 ≤100MB/30min | 实测（`nvidia-smi` + 客户端内存曲线） | AI 默认（依据本机实测） |
| NFR-06 | 兼容性 | 高 | Android **10+**（媒体声音模式硬性要求，麦克风模式 8+ 亦可）；主机 **Windows 10/11**，扩展 E3 后含主流 Linux 发行版 | 兼容测试 | 学生决策（轮 3：Android + Windows） |
| NFR-07 | 安全性 | 高 | 翻译 API 密钥仅存在于服务端 `.env`；**客户端 APK、代码仓库、服务端日志中均不得出现** | 代码审查 + 推送前扫描 | 行业惯例 |
| NFR-08 | 易用性 | 中 | 未接触过本项目的新用户，从安装 App 到看到首条字幕 **≤3 分钟**（不含服务端部署） | 演示验证（记录计时） | AI 默认（待确认） |
| NFR-09 | 可扩展性 | 中 | 语言方向、whisper 模型规格、翻译后端均为配置项，替换后**无需改动管道代码**；协议带版本号且向后兼容 | 设计审查 + 新增一个语言对的试做 | 行业惯例＋学生决策（轮 3 扩展计划） |
| NFR-10 | 成本 | 低 | 单句翻译**输入 ≤200 tokens、输出 ≤150 tokens**；连续 1000 句累计 **≤350k tokens**；实际用量由服务端逐句统计，按所用模型定价折算成本并记录 | token 用量统计 | AI 默认（待确认：用量上限） |
| NFR-11 | 隐私性 | 高 | 基础版：音频仅经局域网传输，**对外仅发送转写文本**（可由抓包验证）；E2 扩展后音频与文本均不出内网 | 设计审查 + 抓包核验 | 学生决策（轮 4） |
| NFR-12 | 可部署性 | 中 | 在满足 §6 约束的主机上，按 README 可在 **30 分钟内**完成部署并跑通自检（含依赖安装与模型获取）；依赖均有主流平台支持（为 E3 铺路） | 部署演练（建议由未参与开发者实操） | 行业惯例＋AI 默认（阈值 30 分钟待确认） |

## 5. 故障模式与处理

集中定义各故障的**检测 → 降级 → 提示**策略。设计原则：**单点故障不得导致会话中断**，
且任何降级都必须在客户端可见（用户不能拿到"看起来正常但内容是错的"结果）。

| 编号 | 故障模式 | 检测方式 | 降级策略 | 用户提示 | 对应需求 |
|---|---|---|---|---|---|
| FM-01 | 网络中断 / 主机不可达 | WebSocket 断开、心跳 `ping` 超时（>5s） | 保留会话 30s；客户端指数退避重连（1→2→4→8→10s 封顶）；断线期间未断句的半句丢弃 | 状态栏"连接中断，重连中…"；恢复后自动继续，不重复显示已出字幕 | FR-11 |
| FM-02 | 翻译 API 返回错误（鉴权失败 / 服务异常） | HTTP 非 2xx | 重试 2 次（1s/2s 退避）；仍失败则该句**降级回传原文**，`translation` 等于 `source` 并标记 | 悬浮窗该句原文后附"（翻译失败）"；连续 3 句失败则顶部常驻告警 | FR-07、FR-12 |
| FM-03 | 翻译 API 限流 / 超时（>10s） | 429 状态码、请求超时 | 降低并发至 1 并延长退避；超时句按 FM-02 降级；积压超上限（10 句）时丢最旧句 | 同上；积压丢弃时提示"内容过多，已跳过部分语句" | FR-07、FR-12 |
| FM-04 | GPU 不可用或显存不足 | 启动时 `CTranslate2` 设备探测失败；推理抛显存异常 | 启动时自动降级 CPU（`int8`）并显著提示；运行中显存异常则重建引擎，仍失败则停止识别并保留服务在线 | 服务端日志 + 客户端"识别不可用"；**不静默降级**，因 CPU 模式延迟不满足 NFR-01 | NFR-05、FR-20 |
| FM-05 | whisper 模型缺失或损坏 | 启动校验模型目录必需文件（`model.bin` 等）与加载时异常 | 启动失败并给出获取方式（`scripts/download_model.py`）；运行中加载失败则停止接受音频 | 明确报错含修复命令；自检工具将其标为阻断项 | FR-18、FR-20 |
| FM-06 | 媒体声音捕获被拒或被系统终止 | MediaProjection 授权回调失败；采集期间 `AudioRecord` 报错或长时间静音 | 提示改用手动授权重试；仍失败则**降级为麦克风模式**并保持会话可用 | 明确说明"该应用可能禁止音频捕获"，并给出降级按钮 | FR-02、FR-09 |
| FM-07 | 音频帧非法 / 序号丢失 | 帧头 magic 与长度校验失败；`seq` 跳变 | 忽略非法帧并计数；少量丢帧仅记录不中断；连续 10 帧非法则断开该会话 | 丢帧比例超 5% 时提示"音频质量不佳，请检查网络" | FR-03、FR-12 |
| FM-08 | ASR 识别失败（推理异常 / 空结果） | 引擎抛异常或返回空文本 | 丢弃该句并继续下一句；连续 5 句失败则按 FM-04 处理 | 静默丢弃（不打断字幕流），但计入统计；连续失败时告警 | FR-06、FR-12 |
| FM-09 | 音频缓冲或处理队列积压 | 队列长度超上限（10 句） | 丢弃最旧句子，保证最新内容优先 | 提示"处理不及，已跳过部分语句" | FR-05 |

> 说明：`error` 消息的错误码与 `recoverable` 标志定义见 03 文档 §6；本文档规定的是
> **策略与用户可见行为**，不含错误码取值（边界划分同 §3.3）。

## 7. 验收标准

| 编号 | 验收标准 |
|---|---|
| FR-01 | 连接后讲话，服务端收到连续 PCM 数据且无静音截断 |
| FR-02 | 手机播放视频（如 YouTube），字幕随视频语音出现 |
| FR-03 | 服务端按 seq 顺序接收帧，丢帧情况被记录且不影响整句处理 |
| FR-04 | 输入主机局域网 IP 后 3 次连接成功率 100% |
| FR-05/06 | 离线标准音频回放，切句边界与人工标注误差 ≤±300ms，转写文本可读 |
| FR-07 | 100 句英文转写抽检，译文语义正确率 ≥95% |
| FR-08 | 悬浮窗在其他 App 之上可见、可拖动，两行双语正常显示 |
| FR-09 | 会话控制四项操作（开始 / 停止 / 切换采集模式 / 断开连接）均生效且前后状态一致：停止后服务端不再收到音频帧；切换模式后 5s 内新音源开始产出字幕；断开后客户端显示"未连接"且服务端会话被释放（同一 session_id 重连视为新会话） |
| FR-10 | en→zh 方向全链路可用；zh→en 及后续新增语言对在协议层可配置（v1.0 不要求全链路） |
| FR-11 | 断网/服务端重启后 30s 内自动恢复，已显示字幕不重复 |
| FR-12 | 无网络、翻译失败等场景均有明确提示；翻译失败时降级回传原文 |
| FR-18~20 | 在干净环境按 README 完成部署并跑通自检；建议由未参与开发的同学仅凭文档实操验证；翻译密钥等敏感配置不进入仓库 |
| UC-07~09 | 部署者角色验证：能在不求助开发者的情况下独立完成部署、改配置重启、并读懂自检报错提示 |
