# 演示与答辩脚本

| 项目 | 内容 |
|---|---|
| 用途 | 课程演示视频录制 + 现场答辩操作 |
| 适用版本 | 客户端 v0.1.4 (5)；服务端 v0.1.0 |
| 演示设备 | Redmi Pad SE（Android 15 / HyperOS 2.0.208.0.VMUCNXM） |
| 主机 | Windows 11 + RTX 4060 8GB |
| 建议时长 | 视频 4~5 分钟；现场演示 5~8 分钟 |
| 更新日期 | 2026-10-26 |

> 本脚本按当前客户端界面文案编写（「服务器」「采集模式」「悬浮窗字幕」「开始/停止」），
> 操作步骤与 04 文档的 M3 操作单一致。录制前先完整走一遍，确认网络、防火墙、音量与授权。

---

## 1 演示目标

一场演示只需要让观众记住四件事：

1. **它真的能用**：手机播放英文视频/说话，悬浮窗出现中文译文；
2. **两种采集模式都行**：媒体声音（内录）与麦克风（现场）可热切换；
3. **延迟可接受**：句末到字幕上屏 P95 2475ms，观感连贯；
4. **隐私边界清楚**：音频只在私有网络内，云端只收到识别后的文本；密钥只在服务端。

不要把演示变成功能清单朗读。每展示一个功能，就说一句「这解决了什么问题」。

## 2 录制前检查（提前 30 分钟）

### 2.1 主机

| 检查项 | 操作 | 通过判据 |
|---|---|---|
| 服务端已停止旧进程 | 双击 `stop_server.bat` | 提示端口已释放或没有进程 |
| 服务端启动 | 双击 `start_server.bat` | 打印 `服务已就绪`、监听地址、手机端填写 IP |
| 模型加载 | 看启动日志 | `whisper 模型已加载`、`模型预热完成` |
| 翻译配置 | 看启动日志 | `翻译=已配置`（**不要展示 `.env` 或密钥**） |
| 健康检查 | 主机浏览器打开 `http://127.0.0.1:8000/health` | 返回 `status: ok`、`device: cuda` |
| 防火墙 | 已运行过 `network_config.bat` 或 `allow_firewall.bat` | 手机浏览器能打开 `http://<主机IP>:8000/health` |
| 网络 | 手机与主机同一 Wi-Fi/热点，或同一 ZeroTier 网络 | 手机能 ping 通/打开 health |
| GPU 占用 | 关闭游戏、浏览器硬件加速、视频剪辑软件 | `nvidia-smi` 显存空闲约 900MB |
| 磁盘/日志 | `logs/` 可写 | 无磁盘满 |

**建议演示网络**：手机热点直连主机。热点网段由手机分配，IP 可能变化；启动器会打印当前应填地址。若用 ZeroTier，先让手机加入同一 Network 并授权。

**重要**：演示前**不要**在主机上打开 `.env`、翻译控制台或任何含密钥的窗口。录屏会把这些拍进去。

### 2.2 平板

| 检查项 | 操作 | 通过判据 |
|---|---|---|
| 安装正确版本 | 安装 `bilingual-subtitle-v0.1.4-debug.apk` | 页面顶部显示「客户端 v0.1.4 (5)」 |
| 录音权限 | 首次选麦克风时授权 | 系统弹窗已允许 |
| 悬浮窗权限 | 点「前往系统设置授予悬浮窗权限」 | 系统设置中本应用开关已开 |
| 通知权限 | Android 13+ 首次启动授权 | 通知栏可见前台服务 |
| 音量 | 媒体音量调到 60%~80% | 视频声音清晰，不外放过小 |
| 电池/后台 | 关闭省电限制（如系统有） | 切到其他 App 5 分钟不中断 |
| 测试视频 | 本地 MP4（非 DRM）或在线视频 | 能正常播放，画面不黑 |

**媒体声音模式的已知限制**：部分 App/DRM 内容禁止捕获；华为部分机型 ROM 级禁止应用音频捕获（本项目实测图库、第三方播放器、酷狗均为 0%）。演示机用 Redmi Pad SE，已实测可用。

### 2.3 录制工具

推荐两种方式，任选其一：

**方式 A：adb 录屏（画面干净，推荐）**

```bash
# 平板用 USB 连接主机，确认设备
adb devices

# 录屏（不含系统分享/录屏弹窗；最长 180 秒，可分段）
adb shell screenrecord --bit-rate 8000000 /sdcard/demo_media.mp4

# 结束后拉回主机
adb pull /sdcard/demo_media.mp4 .
```

> `screenrecord` 只录画面，不录系统声音；旁白后期配。部分 DRM 视频在录屏中会黑屏，遇到时改用方式 B 或换本地非 DRM 视频。

**方式 B：另一台手机拍摄 + 主机录屏**

- 用另一台手机拍平板屏幕与主机屏幕，能同时拍到「操作动作 + 字幕出现」的因果关系；
- 主机用 Win+G（Game Bar）或 OBS 录服务端启动与 `/status`；
- 后期把两段画中画拼接。

**剪辑**：剪映/Clipchamp 均可。字幕建议后期加关键字幕（不是把悬浮窗字幕再打一遍），突出「媒体声音」「P95 2475ms」「音频不出内网」。

### 3.2 旁白逐字稿（可直接念）

> 这是一个开源、可自托管的实时双语字幕系统。手机负责采集音频，主机负责语音识别和翻译，手机用悬浮窗把双语字幕盖在其他应用上。
>
> 之所以做这个项目，是因为现有商业字幕大多把音频上传到厂商云端。对会议、培训这类场景，音频离开内网本身就是风险。我们的做法是：音频只在私有网络里走，主机做识别，只有识别后的文本发到翻译 API；密钥只存在服务端。
>
> 主机端双击启动脚本，自动加载 whisper 模型并预热，打印手机端要填的地址。客户端只需要填这个地址，打开悬浮窗权限。
>
> 现在演示媒体声音模式：选择媒体声音、开始、授权系统投影，然后播放一段英文视频。可以看到悬浮窗的原文和译文，媒体音量也在变化，说明声音确实被采集到了。字幕可以拖动、调透明度。
>
> 采集中可以直接点麦克风切换模式，不需要退出 App。现在对着平板说话，字幕继续出现。这就是麦克风模式。
>
> 如果网络断开，客户端会自动重连，已经显示过的字幕不会重复。服务端也会记录每一句的识别、翻译和端到端延迟。
>
> 最终 83 句真实场景数据，端到端 P95 是 2475 毫秒，满足 3 秒目标；54 项服务端测试全部通过；100 句翻译由人工逐句复看，全部通过。需要说明的是，翻译评审是单人完成，WER 语料也还没达到 100 句，这些偏差都写在报告里。
>
> 代码、设计文档、测试数据都在仓库里。公网访问和本地模型翻译是下一步的扩展方向。

### 3.3 录制注意事项

1. **先拍「成功证据」再拍细节**：视频前 2 分钟必须出现真实字幕，不要用 3 分钟讲架构。
2. **不要拍系统分享/录屏弹窗**：这是上次演示视频的主要问题。用 `adb screenrecord`，或让另一台手机拍。
3. **不要拍密钥**：启动日志只显示「已配置」，不会打印密钥；但仍要避免打开 `.env`。
4. **字幕要停留 2 秒以上**：说话/播放时留出句末 500ms 静音，让字幕完整出现再切镜头。
5. **出现失败不要剪掉**：如果演示了断网重连或翻译降级，保留「重连中」「翻译失败」提示，这比只展示成功更有说服力。
6. **版本可核对**：画面里保留「客户端 v0.1.4 (5)」，证明运行的是仓库对应版本。

## 4 现场演示流程（5~8 分钟）

### 4.1 开场（30 秒）

「我做的是一个开源、可自托管的实时双语字幕系统。手机采集音频，主机识别翻译，字幕悬浮在其他应用上。核心约束是：音频不出私有网络，密钥只在服务端。」

### 4.2 主机启动（1 分钟）

1. 双击 `start_server.bat`；
2. 指出日志中的「模型已加载」「翻译=已配置」「服务已就绪」；
3. 指出「手机端填写：x.x.x.x:8000」；
4. 浏览器打开 `/health`，指出 `device: cuda`、`degraded: false`。

**讲解点**：启动器会自动识别 ZeroTier/局域网地址，并优先显示当前可达的地址；端口被占用会打印 PID 与处理方式，不会抛原始 traceback。

### 4.3 连接与悬浮窗（1 分钟）

1. 平板打开 App，确认顶部版本 v0.1.4 (5)；
2. 填主机 IP/端口；
3. 打开「显示在其他应用上层」，按提示去系统设置授权；
4. 返回 App。

**讲解点**：悬浮窗开关与系统权限是两条链路；关闭悬浮窗后开关会同步，不需要「关一次再开」。

### 4.4 媒体模式（2 分钟）

1. 选「媒体声音」；
2. 点「开始」，系统弹出投影授权，选择共享范围（建议「整个屏幕」）并确认；
3. 打开预选好的英文视频（本地 MP4 或允许捕获的在线视频）；
4. 让视频播 2~3 句，等悬浮窗出字幕；
5. 指出「媒体音量：xx%」；
6. 拖动字幕到屏幕下方，调低透明度，再调回；
7. 点 × 关闭，再在 App 内打开开关，字幕恢复。

**讲解点**：媒体音量百分比用于区分「捕获到静音」与「链路故障」；部分 App/DRM 禁止捕获，8 秒静音会提示改用麦克风。

### 4.5 热切换麦克风（1 分钟）

1. 保持采集，直接点「麦克风」；
2. 观察日志/状态「采集中」；
3. 对着平板说 2~3 句英文，等字幕；
4. 再点回「媒体声音」，授权新的投影，视频字幕恢复。

**讲解点**：切麦克风不需要新授权；切媒体会重新请求投影。旧投影会先注销再停止，避免 `onStop` 误停新会话。

### 4.6 断线重连（1 分钟，可选）

1. 平板开飞行模式/关 Wi-Fi 5 秒；
2. 指出状态变为「重连中」；
3. 恢复网络，字幕继续；
4. 强调「已出字幕不重复」。

**风险**：现场 Wi-Fi 可能重连慢。若 10 秒内未恢复，不要慌，说明退避策略（1/2/4/8/10s）并直接进入下一环节；视频里已录过成功案例。

### 4.7 数据与收尾（1 分钟）

展示 `/status` 或报告中的表：

- 83 句：P50 1886ms、P95 2475ms；
- ASR P95 1076ms、翻译 P95 1106ms；
- 30 分钟满载：330 句、0 错误/降级，P95 2201.8ms；
- 54 项服务端测试、4 项客户端测试；
- 100 句翻译人工复看 100/100（单人评审，偏差已记录）。

「下一步是 E1 公网 wss + 鉴权，E2 本地模型翻译；E2 完成后音频和文本都不出内网，才真正适合企业保密会议。」

### 4.8 字幕历史（可选，30 秒）

如果评委问「能不能回看刚才的翻译」：

```bash
.venv/Scripts/python.exe scripts/show_history.py --tail 5
```

指出每条的时间、原文、译文、总延迟与翻译失败标记；说明历史默认关闭，本次在 `server/.env`
开启，只写本机 `logs/subtitles.jsonl`（已 gitignore），不会上传或提交。

## 5 失败预案

| 故障 | 现象 | 现场处理 |
|---|---|---|
| 手机连不上主机 | App 一直「未连接」 | 手机浏览器打开 `http://<IP>:8000/health`；不通则检查是否同一网段/防火墙；改用手机热点或 ZeroTier |
| 端口被占用 | 启动日志 `[Errno 10048]` | 双击 `stop_server.bat`；或 `network_config.bat` 改端口；或直接用已运行的服务端 |
| 模型加载慢/失败 | 日志停在「加载模型」 | 等待 30s；检查 `models/faster-whisper-medium/model.bin`；用 `scripts/check_env.py` |
| 翻译失败 | 字幕只有原文/附「翻译失败」 | 这是降级行为，可作为健壮性演示；检查网络与 DeepSeek 余额；不要现场打开 `.env` |
| 媒体模式无字幕 | 媒体音量 0% | 换本地非 DRM 视频/第三方播放器；或改麦克风+外放兜底；说明华为 ROM 限制案例 |
| 悬浮窗不显示 | 有字幕但看不到浮层 | 检查系统「显示在其他应用上层」；关闭再开开关；确认未被系统清理 |
| 投影授权被拒 | 无法开始媒体模式 | 重新点「开始」再授权；或先演示麦克风模式，媒体模式用预录视频补充 |
| 平板没电/断连 | 采集中断 | 提前充满电，关闭省电限制，准备备用机/预录视频 |
| 现场网络极差 | 延迟明显升高 | 改用手机热点直连；或直接播放预录视频 + 主机 `mock_client.py` 演示服务端链路 |

**兜底方案（必须提前准备）**：

1. 预录 2~3 分钟成功演示视频（媒体模式 + 悬浮窗）；
2. 主机上准备离线音频与 `scripts/mock_client.py`，可在无手机时展示「音频→字幕」链路；
3. 准备 `/status`、`/latency` 的截图或 JSON，网络异常时用数据说明。

## 6 答辩问答准备

| 问题 | 回答要点 |
|---|---|
| 为什么不用手机本地识别？ | 手机端 whisper 推理速度/功耗不可接受；主机 GPU 可做到 0.4~1.1s/句，且模型可统一升级。 |
| 音频真的不出内网吗？ | 基础版音频只经局域网/ZeroTier 到自有主机；发往 DeepSeek 的只有文本。E2 换本地模型后文本也不出网。未做抓包是已知偏差。 |
| 为什么按句翻译，不做逐字流式？ | 逐字重译会导致译文反复抖动；按句稳定，1~3s 对字幕可接受。协议预留了 `partial` 消息作为 v1.1 折中。 |
| 延迟 2475ms 是怎么算的？ | 每帧记录真实到达时刻，句末按 `end_ms` 查表，用 `created_ms - 到达时刻`；不是「首帧 + 标称位置」估算。 |
| 为什么用 8s 切句？ | 15s 长句使 ASR 尖峰拉高 P95 到 5.2s；8s 后单句绝对耗时下降，P95 2.5s；用户确认观感良好。4s 更快但切句太碎。 |
| 媒体声音为什么华为不行？ | 图库/第三方播放器/酷狗均 0% 电平，判定为 ROM 级捕获限制，不是链路故障；Redmi Pad SE 实测通过。 |
| 密钥安全吗？ | 只在 `server/.env`，gitignore 排除；客户端/仓库/日志/协作记录均无；提交前扫描。 |
| 能支持多个手机吗？ | v1.0 只验证单客户端；服务端状态按 Session 隔离，多客户端需要增加调度队列，架构不需要重构。 |
| 公网能用吗？ | 当前是局域网 ws；E1 需要 wss + token 鉴权 + frp/云服务器，协议不变。不能把明文 ws 直接暴露公网。 |
| 翻译质量怎么保证？ | 100 句真实翻译 + 人工逐句复看 100/100；但只有一名评审，未满足双人独立评审程序，报告已如实记录。 |
| WER 是多少？ | 17.3s 夹具 WER 0.0%，但语料规模不够 NFR-03 的 100 句/10 分钟，只能算链路验证，不能算正式达标。 |
| 成本多少？ | 100 句约 0.026 元；83 句 M3 约 0.031 元；服务端累计 token 并达阈值通知。 |
| AI 做了什么？ | 需求/设计/代码/测试/文档均有 AI 参与；人负责决策、设备、密钥、评审与验收。完整记录在 `docs/AI协作记录.md`。 |
| 最大的技术难点？ | 不是单点算法，而是实时链路的口径与生命周期：VAD 状态、延迟时钟、重连时序、悬浮窗/投影生命周期。报告 §4.5 有完整的问题表。 |
| 如果重做，会改什么？ | 更早做可观测性（电平、逐句延迟）、更早补 WER 语料与双人评审、把 NFR-04 的 30 分钟采样纳入 M3 而不是 M5。 |
